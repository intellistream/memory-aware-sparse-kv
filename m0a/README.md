# M0-A native selected-set observation

The project is **memory-aware-sparse-kv**. Some pinned image names, environment
variables, and archived run IDs below retain their historical identifiers.
Commands that use `/workspace` or a private Docker socket describe the old
workspace and are unavailable on the rebuilt Pod. The current DeepSeek launcher
prints a dry-run plan and blocks `--execute` pending a verified Pod adapter.

## Status

Stage 0 is sealed. The local baseline contains 16 serving configurations with
320/320 successful requests, a three-run 32-token deterministic check, and the
eight-rank profiler parse manifest. The complete 2.6 GB parsed profiler remains
on `hust`.

M0-A has a read-only hook immediately after
`npu_vllm_quant_lightning_indexer` in the DSA context-parallel prefill path.
Tracing is disabled when `VLLM_ASCEND_M0A_TRACE_DIR` is empty. When enabled, it
copies only configured output rows, writes per-rank JSONL, and returns the
original tensor unchanged. Serving has no prefetch/offload policy. A separate CPU-only Transition Table and
working-set cache replay is implemented in `transition_replay.py`; see
[`docs/transition-working-set-cache.md`](../docs/transition-working-set-cache.md).

The DeepSeek live NPU pilot `m0a_pilot_20260924_rerun03` completed serving and both
requests. It captured 672 native rows and reproduced the accepted Stage 0
32-token output exactly. The original run manifest says `failed` because the
first validator assumed exact equality between public API and internal engine
request IDs and expected 20 DSA layers. Runtime evidence showed a unique
per-request engine suffix and 21 DSA layers (even layers 2--42). The corrected
validator and independent artifact audit pass on the preserved raw files. The
pilot gate is open; the paired DeepSeek experiment and representative real-agent
corpus have not run.

A separate single-NPU engineering lane now uses the tiny
`inference-optimization/GLM-5.3-0.6B-A0.4B` model. Its trace-off baseline,
trace-on native SFA pilot, and a 72-request equal-length synthetic run passed on
NPU 0. The accepted run is
`m0a_glm53_pairs_equalized_20260926_r02`: 8,424 trace rows, six layers per
request (three computed and three index-cache reuse), exact matched prefixes,
and 24/24 repeat-signature groups stable. This is engineering prevalidation
only because the tiny model is random-initialized/toy-fine-tuned, BF16, six
layers, and lacks MTP. See `docs/glm53-single-npu-prevalidation-report.md`.


The verifier checks every run ID against its raw JSON and log, checks 320/320

### Prepare real agent workloads

`import_workloads.py` accepts redacted runtime-neutral JSONL. Each input row has:

```text
workload_id, episode_id, source_trace_id, event_type, context_target,
prefix, event_text, control_text, postfix
```

Run it in the pinned trace image, which contains the tokenizer library, while
mounting the model and output paths from the host:

```bash
DOCKER_HOST=unix:///workspace/memecho/runtime/docker.sock docker run --rm \
  --entrypoint python3 \
  -v /workspace/memecho:/workspace/memecho \
  memecho/m0a-trace:stage0-v3 \
  /workspace/memecho/m0a/import_workloads.py \
  --input /workspace/memecho/m0a/workloads/redacted.jsonl \
  --tokenizer /workspace/memecho/models/DeepSeek-V4-Flash-w8a8-mtp/tokenizer.json \
  --output /workspace/memecho/m0a/workloads/pairs.json
```

The importer rejects unknown events, duplicate pairs, non-single boundaries,
event/control lengths differing by more than two tokens, or prompts outside the
context target tolerance. `workload_input.example.jsonl` documents the input
shape; it is not a research workload.

The formal corpus target is at least two representative workloads. For each
workload, prepare two independent episodes for each of the six event types at
8K and 32K: 24 independent matched transitions per workload. The existing 12
pairs in `pairs.json` are synthetic smoke inputs and do not satisfy this gate.

## Artifact contracts

Run, pair, and response artifacts use `schema_version: 1`. Native trace rows
use schema v1 for DeepSeek and model-aware schema v2 for GLM. All are validated
by `contracts.py`:

- pair set: pinned tokenizer hash, workload/episode identity, one boundary, and
  exact prompt-token hash;
- response JSONL: run/request/pair identity, timing, prompt hash, and output
  signature;
- trace JSONL: request/rank/layer/position, all 512 native IDs including `-1`,
  compression ratio 4, compressed-cache block size 128, mapped logical blocks,
  and timestamp;
- GLM trace JSONL: model identity, SFA operator/source, all 2,048 native KV
  token positions, ratio 1, logical block size 128, and timestamp;
- run manifest: immutable run directory, commands, source artifact hashes, and
  terminal status;
- analysis JSON: per-pair repeatability plus per-workload/event/context effects
  whose statistical unit is the independent episode.

The analyzer fails on missing or duplicate layer/token rows, rank filename
mismatch, run mismatch, unexpected width/unit/sentinel, out-of-causal-range
native indices, incorrect block mapping, missing variants, or mismatched prefix
selected sets. Identical replays assess runtime stability and are never counted
as independent experimental samples.

The public API request ID and vLLM engine request ID are related but not
identical: the engine appends a per-request suffix. Validation maps the engine
ID to exactly one public ID by an anchored prefix and retains both identities
in the analysis inventory.

The orchestration CLI is a dry run unless `--execute` is supplied:

```bash
cd /workspace/memecho
python3 m0a/orchestrate.py pilot --run-id m0a_pilot_YYYYMMDD
python3 m0a/orchestrate.py pairs --run-id m0a_pairs_YYYYMMDD
```

For single-card GLM engineering checks, use the model profile and an idle card:

```bash
bash m0a/download_glm53_tiny.sh
bash m0a/build_glm53_image.sh
python3 m0a/orchestrate.py baseline \
  --run-id m0a_glm53_baseline_YYYYMMDD \
  --model-profile glm53_tiny --device 0 --execute
python3 m0a/orchestrate.py pilot \
  --run-id m0a_glm53_pilot_YYYYMMDD \
  --model-profile glm53_tiny --device 0 --execute
python3 m0a/orchestrate.py pairs \
  --run-id m0a_glm53_pairs_YYYYMMDD \
  --model-profile glm53_tiny --device 0 --repetitions 3 --execute
```

The GLM profile requires exact event/control token-length equality. A prior
32K run showed deterministic prefix selected-set differences when total prompt
length differed by one token, because chunk execution shape also changed.
`equalize_synthetic_pairs.py` prepares the synthetic smoke corpus; real
workload controls must be reviewed rather than padded automatically.

After an exclusive eight-card reservation is active, run:

```bash
python3 m0a/orchestrate.py pilot \
  --run-id m0a_pilot_YYYYMMDD --execute
```

The accepted pilot evidence is under
`m0a/runs/m0a_pilot_20260924_rerun03/`. Its `pilot_validation.json` passes
native index range/padding/mapping, 21-layer coverage, request linkage, and
exact Stage 0 32-token output identity. The next command is:

```bash
python3 m0a/orchestrate.py pairs \
  --run-id m0a_pairs_YYYYMMDD \
  --pairs m0a/pairs.json \
  --repetitions 3 \
  --execute
```

Each run gets a new `m0a/runs/<run_id>/` directory. The orchestrator refuses to
reuse it, refuses to start while either research or baseline container is
running, captures NPU snapshots and server logs, applies a finite health
timeout, and stops the trace container on success or failure.

## Native index interpretation

Source inspection indicates that the A2 kernel uses `-1` for invalid entries.
The returned indices are positions in compressed KV sequence order. For this
model path, the logical compressed-KV block is `raw_index // 128`; physical
cache block IDs are deliberately excluded from selected-set identity. Live
pilot validation remains mandatory before this interpretation is accepted as
experimental evidence.

The primary M0-A measures are selected-set Jaccard and new-block rate across
the adjacent positions `boundary-1` and `boundary`, paired against a same-prefix
control. No latency or KV recall cost is inferred from M0-A traces.

## Offline Transition working-set replay (2026-09-28)

`working_set.py` and `transition_replay.py` provide exact-prefix candidate validation,
source-backed compressed-KV support requirements, bounded per-layer transition
statistics, and lossless LRU replay at native and 128-token-page granularity.
Every strategy has the same explicit capacity and prefetch byte budget. Held-out
sessions/episodes/pairs/source traces are isolated; evaluation never updates tables.

```bash
python3 m0a/transition_fixture.py --output-dir /tmp/transition-fixture-NEW
python3 m0a/transition_replay.py \
  --trace-dir /tmp/transition-fixture-NEW/traces \
  --sidecar /tmp/transition-fixture-NEW/sidecar.json \
  --config /tmp/transition-fixture-NEW/config.json \
  --output-dir /tmp/transition-replay-NEW
```

This fixture is engineering-only. Existing boundary-only traces cannot fill the
32-token window, and real DeepSeek region learning is refused without validated
compressor support intervals. Sequential selected-set replay is not labeled ECHO;
CPU timestamps are not recall-stall measurements. See the linked document for the
sidecar contract, results, sync ledger, artifact lineage and online gates.
