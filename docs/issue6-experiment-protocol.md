# Issue 6：任务 1–10 的统一实验协议

协议版本 1。实现接口见 `m0a/issue6_protocol.py`，统一评估入口为
`m0a.issue6_evaluate`。默认研究模型仍为项目指定的 DeepSeek-V4-Flash W8A8；
本套单卡实验使用已封存 GLM tiny 辅助模型，模型能力与结果适用范围分别验收。

## 预测对象与时间

预测对象是单请求、单 rank、单层、单阶段下的逻辑 KV token。当前 GLM 适配
固定为六层、2048 个原生选择槽；padding 为 -1。逻辑 128-token 页映射同时保留
在原始 trace，统一缓存模拟以 token 为单位，不混用页数和 token 数。

每个预测器绑定 `(task, run, request, context_version, rank, layer, phase)`。
`context_version` 是实际 prompt token IDs 的 SHA256。请求、上下文版本、层
或 prefill/decode 改变时建立新实例；不同请求的相同整数 ID 不共享统计。
阶段 occurrence 改变时 stage 历史与自适应反馈冷启动，global 历史保留在当前
KV 命名空间内。当前真实受控输入每请求只有一个 decode 阶段，不能据此声称
跨真实工具事件或跨阶段持续性已经成立。

`Context` 是不可变数据，只含预测前可见的 query、时间、阶段、候选空间、
需求文本、精确片段映射和可选 score。它不接受当前或未来的 selected set。
`Observation` 在该 query 完成后单独发布选集。连续 decode query 从 0 编号，
逻辑时间为预测 `2q`、完成 `2q+1`；校验器拒绝缺行、乱序和重叠可见性。
这些是离线因果顺序，不是实测的预取提前量。

query 位置为 p 时，预测候选空间是半开区间 `[0,p)`，不含当前新 KV。
原生 attention 可选择位置 p，该位置只能在缺失召回阶段处理。需求文本和
输入 prompt 在请求到来时已经可见；片段只映射到本命名空间内已生成的 KV。
语义候选按精确 token span 截取，不从后续选集构造候选空间。

prefill 的 query 批次不能把同一批次的前驱选集当作已完成历史。原始采集保存
批次起点、大小和实际长度，前驱可见性据真实批次确定。当前只采样 prefill 窗口，
因此 prefill 仅作捕获/score 正确性检查；缓存回放只接收完整连续 decode 窗口，
不将采样窗口伪装成完整 prefill 执行。

## ECHO 的信号边界

无预取、上一选集、访问历史、语义 LSA、学习到的区域先验和自适应组合都遵守
同一预测接口。ECHO-style decode 使用当前完整 indexer score 和已完成 query
的 kth-score EMA，alpha 固定为 0.5；第一 query 没有阈值，冷启动不预取。
阈值筛选保留逻辑 ID 的流顺序并截断预算，不用当前精确 top-k 重排候选。
已有 `m0a.echo_replay` 保留 prefill 256-bin 参考实现和测试；本次缓存比较
覆盖 decode EMA 部分，不声称复现论文完整在线系统。

完整 score 从真实 BF16 indexer 输入重建，并逐 query 对照原生 top-k。
该诊断发生在 native indexer 输出后，且会同步设备；它不证明 score 能在
线上选集产生前送达或搬运能与计算重叠。报告把此 signal 可用时刻与零拷贝
提前量分开，ECHO 的 CPU 预测开销也不包含 native score 重建时间。
selected-only trace 缺少完整 score，不能凭选集伪造 ECHO 输入。

oracle 在评估器内部于预测之后单独构造，先选可搬运的缺失原生选集，再以
已驻留的原生项补齐候选预算，作为候选覆盖率预算上界。它不写入其他预测器
或学习状态；共同 LRU 的规则仍适用，因此不是整条缓存轨迹的最优淘汰 oracle。

## 公平缓存口径

每种策略使用相同每层容量 C、每 query 候选预算 P、LRU 淘汰和缺失召回规则。
默认 C 为 4096/8192 tokens，P 为 128/512 tokens。每个请求/层的 decode 窗口
从空缓存开始，不假设完整 prefill 已经暖缓存。C 必须容纳原生当前选集，P≤C。
候选最多 P 个且去重；已驻留候选不再搬运。预取时不能保护尚未知晓的当前选集，
因此错误预取导致的污染和额外同步回载会计入结果。

原生选择完成后，缺失项同步回载，当前完整选集受保护，随后更新共同 LRU。
每次预取的副本在首次使用时计为有用，使用前淘汰或窗口结束仍未使用则计为浪费。
恒等式为 `prefetched = useful + wasted`；总搬运为预取加同步回载。
默认每 token 每层数据量为 `(512+64)*2 = 1152 bytes`，对应 GLM 的 BF16
压缩 KV 与 RoPE payload，不包括常驻 indexer key、页表或其他模型状态。
容量及字节量都是离线模拟，不能作为实测 HBM 节省或 DMA 性能。

候选精度为命中候选/候选数，原生覆盖率为命中候选/原生选集大小。无候选时
精度约定为 0。缓存命中、同步回载、浪费预取和候选命中分别报告；候选命中
不等于缓存收益，预取也可能增加总搬运。

## 数据、学习和统计

两域各六个独立任务，以固定排序及 index mod 3 分为 train/validation/test，
每域每个划分两个任务。所有分支、对照和重放重复共享原始 task ID 的划分。
原始 task、业务事实、评价动作、策略和数据库不改写；非周期对照是只读自然
对话与无关天文摘录，作为额外上下文并保留 provenance。天文摘录不是实际
benchmark 工具返回，不虚构工具调用记录。
新增输入对照不重复填充中性句子；模型生成的校准续写仍可能出现短循环，
固定续写与 tiny 模型能力限制继续保留，不将非周期输入误写为自然 Agent 续写。

本次受控 replay 的银行输入披露完整客户 scenario（含模拟器指令），该输入
不能算自主 Agent 的有效任务完成证据。真实 GLM/GLM benchmark 运行和单独
seeded-customer Agent 探针另存原始 request/response/tool logs。只有真实成功
工具调用并继续读取结果，才能将工具闭环能力标为通过。

LSA 的词表、IDF 和最多 16 维投影仅用训练任务片段拟合，CPU 词袋分布语义
基线的范围明确，不称为预训练神经语义编码器。索引使用请求内 128-token
片段，保存编码、索引、检索开销。词表最多 1024，训练片段最多 512。
事件模型仅用训练任务的原生标签拟合 16 个相对位置区域的分布，按层、phase、
事件类型和请求窗口位置条件化；与无事件条件先验、纯事件、纯历史作消融。
当前受控 native 数据只有 task_request 类型，无法证明真实工具事件增益。

自适应组合在历史、LSA、事件和顺序候选间分配同一 P，采用过去已完成 query
反馈的精度 EMA 与 0.05 探索下限；最大余数法分配整数预算、去重并补足空缺。
无语义、无事件和固定配额版本作消融。EMA 与所有超参数在读测试标签前固定，
验证集不用于测试期在线调参；oracle 标签不可进入组合权重。

只在 test tasks 上报告指标。先在独立任务内合并层、query 和同任务变体，再
计算 task macro mean 与 seed 7、1000 次 task-cluster bootstrap 的 95% 区间。
原始/对照各自也单列。重复 query 或重放不增加独立样本量；不足两个任务时
区间为 null。小样本区间只能解释这份受控数据，不推广为真实 Agent 泛化结论。
